# MarchMap

Android-first GPX viewer: React Native 0.86, TypeScript, Expo SDK 57, MapLibre Native 11, Turf, SVG. GPX обрабатывается на устройстве. Нет аккаунтов, сервера приложения или фонового GPS-слежения.

## Standalone APK

Версия 1.3.0, `artifacts/MarchMap-1.3.0.apk`, приложение **MarchMap**, пакет `com.marchmap.standalone`, versionCode 5. Обновляет предыдущие standalone-сборки без смены пакета. ARM64 (телефоны) и x86_64 (эмулятор). JavaScript/Hermes bundle включён; Expo Go и Metro не нужны. Expo dev client/launcher/menu отсутствуют. APK для тестирования подписан стандартным ключом Expo-шаблона; для публикации нужен собственный upload key.

## Использование

- **+** справа вверху: импорт GPX до 25 МБ через системный выбор файла. Корректный маршрут сохраняется в библиотеке.
- **Папка** в шапке: список локальных маршрутов, переключение и удаление. Последний выбранный маршрут восстанавливается при запуске.
- В файловом менеджере выберите GPX → «Открыть с помощью» → **MarchMap**. Поддерживается также «Поделиться» одним GPX. Файл копируется по временному разрешению Android, исходник не изменяется.
- **Значок местоположения** над картой: одно измерение GPS с запросом foreground permission.
- Тап по карте или перетаскивание по профилю выбирает точку маршрута. Профиль перемещает камеру к выбранной точке. Оранжевый маркер и показатели синхронизированы. Синий GPS остаётся независимым.
- Карта, показатели точки и профиль находятся на первом экране. «Сбросить» возвращает показатели GPS (или старта, если GPS не на маршруте).
- **Настройки**: режим карты, состояние скачивания, прогресс, объём ресурсов и повторная загрузка после ошибки.

## Режимы карты

По умолчанию **Офлайн + онлайн-подгрузка**. Выбор записывается в `Paths.document/map-mode.txt` и восстанавливается при запуске.

1. **Только офлайн**: импорт запускает подготовку области. Интернет разрешён карте во время подготовки; после завершения или ошибки `NetworkManager.setConnected(false)` запрещает сетевые запросы MapLibre. За пределами сохранённой области возможна пустая подложка.
2. **Офлайн + онлайн-подгрузка**: область маршрута хранится в постоянной нативной offline DB. Вне неё работает обычная онлайн-карта. Без сети сохранённая область остаётся доступной.
3. **Только онлайн**: нет предварительной загрузки; карта запрашивает данные при просмотре. Обычный HTTP-кэш и ранее скачанные области не удаляются.

Используется [OpenFreeMap Liberty](https://openfreemap.org/quick_start/), векторные данные OpenStreetMap/OpenMapTiles без ключа. [Публичный сервис](https://openfreemap.org/) не ограничивает число запросов. Атрибуция сохранена в стандартной кнопке карты.

Область скачивания: bounding box всех сегментов плюс 0.01° по каждой стороне, масштабы 0–14. Это запас примерно 1 км по широте; по долготе он зависит от широты. Более крупные масштабы увеличивают сохранённые векторные тайлы. Для очень больших bbox объём может быть значительным. Полярные области за ±85° и переход через 180° не поддерживаются подготовкой: отображается ошибка, GPX остаётся доступен.

Статусы: не загружена / загрузка / готова / частично загружена / ошибка. Процент и размер сообщает native OfflinePack; размер — ресурсы пакета, не полный размер файла БД. При ошибке скачанные данные сохраняются; повторная попытка продолжает пакет. Через 90 секунд без прогресса показывается ошибка с повтором. Для подготовки оставляйте приложение открытым. При смене режима/маршрута предыдущая загрузка приостанавливается, устаревшие callbacks игнорируются. Готовая область переиспользуется при повторном импорте такого же bbox. GPX, GPS и выбранная точка не удаляются при смене режима.

GPX хранятся в приватном `Paths.document/routes/` вместе с двухслотовым журналом библиотеки. Сохраняются список, активный маршрут и намерение не загружать карты после очистки. Повторный импорт идентичного XML не создаёт дубликат. GPS остаётся только в памяти и обновляется по кнопке.

Кнопка «Удалить все скачанные карты и кэш» в настройках останавливает загрузки, удаляет offline-пакеты и ambient cache. GPX сохраняются. Карты не скачиваются автоматически после очистки и перезапуска; используйте «Повторить загрузку» или импорт нового GPX. В онлайн/гибридном режиме просмотр карты снова наполняет обычный кэш. Удаление GPX из списка не удаляет общие offline-тайлы других маршрутов.

## Локальная сборка

Node.js 22.13+ (проверено 24.14), Android SDK, JDK 21. Нативная папка генерируется из `app.json`, не хранится в Git. Локальный Expo-модуль `modules/marchmap-incoming` хранится в Git и подключается autolinking автоматически. Он принимает Android VIEW/SEND, читает content URI через ContentResolver и ограничивает копирование 25 МБ. Android MIME-фильтры включают GPX/XML/octet-stream, поскольку файловые менеджеры по-разному определяют GPX. Имя и содержимое проверяются до добавления маршрута.

Исходный логотип: `assets/logo.png`. Оптимизированные wordmark/symbol, обычная, adaptive и monochrome иконки воспроизводятся командой `python scripts/prepare_brand.py` (Pillow).

```powershell
npm ci
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
$env:EXPO_NO_TELEMETRY = '1'
npm run prebuild
$env:NODE_ENV = 'production'
cd android
.\gradlew.bat :app:assembleRelease '-PreactNativeArchitectures=arm64-v8a,x86_64' '-Dorg.gradle.jvmargs=-Xmx3072m -XX:MaxMetaspaceSize=1536m -Dfile.encoding=UTF-8' --console=plain --max-workers=2
```

Результат: `android/app/build/outputs/apk/release/app-release.apk`. Для разработки `npm run android` собирает debug-вариант, которому требуется Metro. EAS-профиль `preview` также создаёт standalone APK.

```powershell

```

Тесты проверяют расстояния, snap и GPS threshold, разрывы сегментов, отсутствующие высоты, дубли, 6000 точек, двусторонний выбор карта/профиль, неверные расширения и размеры, XML не того формата, повреждённые точки и высоты, сохранение настроек, три режима offline controller, ошибки загрузки, готовые пакеты и устаревшие callbacks.

Ручная проверка Android: импорт `samples/berlin.gpx`, жесты профиля и карты, GPS внутри/вне 30 м, скачивание до «Готова», смена режимов без потери GPX, перезапуск и повторный импорт с отключёнными Wi-Fi/data. Неверные файлы не должны заменять открытый маршрут. APK проверять без `adb reverse` и Metro.

## Модель маршрута

- GPX `trk/trkseg/trkpt`, namespaces и несколько треков. `rte` и waypoints не импортируются.
- Дистанция геодезическая, суммируется только внутри сегментов. Разрывы не соединяются линией или профилем.
- Snap через Turf выбирает ближайший реальный сегмент. GPS progress показывается в пределах 30 м. На самопересечениях без истории движения выбирается первое равноудалённое место.
- Высоты интерполируются из GPX, отсутствующие значения остаются null. GPS altitude не подменяет их.
- Профиль использует те же cumulative distance, сферическую интерполяцию координат и линейную интерполяцию высот. Для screen reader доступны действия вперёд/назад.
- Исходный файл не изменяется, временная копия удаляется. Невалидный импорт показывает ошибку и сохраняет прежний маршрут.
- GPS только по нажатию, без watchPosition, background permissions и истории.

## Языки

Интерфейс доступен на русском, английском и немецком. При первом запуске используется язык устройства (для остальных языков — английский). В настройках можно выбрать язык вручную или вернуть системный; выбор хранится в приватном `language.txt`. Переключение не меняет маршрут, выбранную точку или карты. Названия маршрутов из GPX и географические названия подложки сохраняются как в источнике. Системный выбор файлов и разрешения Android используют язык системы.

Переводы находятся в `src/i18n/messages.json`; тесты проверяют полноту ключей, параметры строк, формат чисел, сообщения ошибок и сохранение настройки. Неизвестные технические ошибки заменяются понятным локализованным сообщением.

## Значимые подъёмы (1.3.0)

`buildRoute` после GPX-парсинга один раз создаёт отдельный профиль и сохраняет технически допустимые кандидаты в `route.climbCandidates`, а значимые — в `route.climbs`. Профиль маршрута не меняется. При загрузке сохранённого GPX строится новая модель; при GPS, выборе точки или рендере анализ не запускается. Изменение чувствительности фильтрует готовых кандидатов без повторного чтения GPX или сглаживания. Карта/офлайн-контроллер не перезапускаются из-за изменения чувствительности.

- Расстояния в модели — км, высоты — метры. Ресемплинг: 25 м; центрированная rolling median: окно 100 м (5 отсчётов), симметрично уменьшается у границ. Любая отсутствующая высота и каждый GPX track segment разделяют анализ.
- Начало тренда: локальный уклон ≥0,5%, прирост ≥5 м. Короткие полки и спуски остаются внутри кандидата. Допустимый dip: до 200 м и 15 м потери; значимый устойчивый спад: 20 м. Плато: 250 м с приростом не более 8 м, при отсутствии возобновившегося значимого восходящего уклона. Конец кандидата — последний максимум, а не конец подтверждающего спуска/плато.
- Технические минимумы: 250 м, 30 м набора и 3% среднего уклона. Gain/средний уклон считаются как чистая разность высот начала и вершины, с включением длины допустимых полок/dip.
- Значимость: `distanceKm × averageGradePercent²`. High / medium / low: 20 / 40 / 80. По умолчанию medium. Пресеты не меняют детектор или сглаживание.
- Своя настройка: `(distanceM / 1000) × grade²`, например 6% / 800 м = 28,8. Динамические примеры учитывают также минимальную длину/набор и округляются вверх до 50 м. Настройка хранится в `climbs.json`; ошибочная запись не меняет активную настройку.
- Карточка использует только snapped GPS-позицию внутри `[startDistance, endDistance)`. Высота в текущей точке интерполируется по исходным GPX-точкам двоичным поиском. GPS altitude и selected point не участвуют. Остаток должен превышать 100 м пути и 10 м высоты. Поиск статуса — O(log climbs + log points).
- Все параметры в `src/config/climbs.ts`; чистые функции — `src/services/climbs.ts`. Тёмная/светлая темы и RU/EN/DE поддержаны.

Воспроизводимый отчёт: `node scripts/climb-report.cjs`. Замер — только preprocessing + detection в Node.js на рабочем компьютере, медиана после прогрева; это не замер телефона или XML-парсинга. На `samples/berlin.gpx` (8 точек) high/medium/low: 0/0/0, около 0,036 мс. На синтетическом `samples/climbs-demo.gpx` (185 точек, 4,6 км): 3/2/1, около 0,088 мс. На 10 001 точке / 100 км: около 2,72 мс, p95 около 8 мс.
